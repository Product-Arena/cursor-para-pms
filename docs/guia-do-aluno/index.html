Recursos dos agentes (Rules, Commands, Skills)

Três alavancas que estendem o comportamento do agente sem repetir contexto em todo prompt.

Objetivo: Saber o que são Rules, Commands e Skills; aplicar duas práticas de workspace mais seguras e conscientes de contexto.

4.1 Rules, Commands e Skills

Contextualizar que existem três recursos importantes que funcionam em conjunto com os agentes:

  1. Rules — instruções persistentes (manual de estilo, convenções).
  2. Commands — atalhos que disparam fluxos (/comando).
  3. Skills — pacotes de comportamento e templates instaláveis.

4.2 Dicas para workspace mais otimizado

  1. Desabilitar a deleção de arquivos (configuração de segurança/comportamento do agente).
  2. Manter a rule general-guidelines em always apply e explicar o impacto na janela de contexto (por que isso importa para PMs).

Construindo o seu “Start My Day”

Fechar o dia com uma visão sistêmica: uma rotina repetível que combina métricas, gestão de tarefas e o que você já usou no curso.

Objetivo: Estruturar em modo Plan (ou Agent) um fluxo matinal que faça sentido para PM — inspirado em referências da comunidade Cursor.

8.1 Por que “Start My Day”

  • Contextualizar como a turma deve pensar de forma sistêmica no Start My Day.
  • Referência: exemplo do Ben Berube (Cursor) — pega tarefas do board, classifica por complexidade, elege um agente para trabalhar nas mais simples primeiro.
  • Para PMs: começar o dia atualizado em métricas, andamento de entregas, agenda e reuniões importantes.

8.2 Construção do Start My Day

  • No modo Plan, montar um .md que estruture os passos necessários para o SMD.
  • Ações previstas no fluxo (exemplo):
    1. Atualizar os dados das métricas
    2. Pegar no Linear o status das tarefas
    3. Salvar local (artefatos/resumo)
    4. Preparar a build para uma nova interface
    5. Construir a interface (entrega visual/dashboard/resumo — alinhar formato final na produção do material)

Comandos para acompanhar status, registrar mudanças e sincronizar com o remoto.

1. Status atual

ComandoFunçãoQuando usar
git statusArquivos modificados, adicionados ou não rastreados.Antes de commitar.
git logHistórico de commits.Revisar o que foi feito.
git diffDiferenças linha a linha.Ver o que mudou em um arquivo.

2. Preparar e registrar alterações

ComandoFunçãoUso
git add <arquivo>Adiciona à staging.Primeiro passo antes do commit.
git commit -m "msg"Salva com mensagem curta.Checkpoint do trabalho.
git commitAbre editor para mensagem longa.Mensagens detalhadas.

3. Sincronizar com o remoto

ComandoFunçãoObjetivo
git pullBaixa e mescla do remoto.Manter cópia atualizada.
git pushEnvia commits locais.Compartilhar mudanças.
git fetchBaixa sem mesclar.Inspecionar antes de integrar.

4. Branches

ComandoFunçãoUso
git branchLista branches.Ver linhas de trabalho.
git checkout -b <branch>Cria e troca para novo branch.Feature ou correção.
git checkout <branch>Troca para branch existente.Navegar entre branches.
git merge <branch>Mescla outro branch no atual.Unir trabalho.

5. Casos de uso (copiar no terminal)

Consultas rápidas:

  • Histórico conciso: git log --oneline -10
  • Desfazer mudança não commitada: git checkout -- arquivo.md
  • Diferenças totais: git diff
  • Por arquivo: git diff arquivo.md
