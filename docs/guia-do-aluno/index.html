Configurando seu workspace

Organizar a IDE e a pasta .cursor é preparar o terreno para referências e contextos estáveis para os agentes.

Objetivo: Ajustar o Cursor ao seu fluxo visual; entender o workspace modelo e por que a raiz .cursor importa para PMs.

Parte expositiva — Ajustes de interface 10 min

O instrutor mostra como ajustar theme, tamanho da fonte e organizar os painéis (sugestão: sidebar à esquerda, editor e terminal no centro, chat à direita).

Estrutura do workspace modelo

O workspace já vem com pastas organizadas e uma pasta .cursor/ na raiz. Essa pasta centraliza rules, commands e templates — o que permite aos agentes consultarem referências estáveis sem você repetir contexto a cada prompt.

Conceitos importantes

Checklist, IDE e GitHub são o vocabulário mínimo para trabalhar como builder dentro do Cursor.

Objetivo: Validar pré-requisitos; alinhar o que é uma IDE e o papel do GitHub no curso; garantir que todos clonaram o repositório com o material.

Parte expositiva — Checklist e vocabulário 10 min

Conferência rápida dos pré-requisitos (Cursor, GitHub, Notion, Linear) e nivelamento sobre o que é uma IDE e o papel do GitHub como plataforma de versionamento e colaboração — não só "coisa de dev".

Na apresentação: contexto e demo. Neste guia: ordem dos passos, prompts e entregáveis — sem repetir a mesma explicação dos slides.

Modos de uso (Ask, Plan, Agent e outros)

Os modos definem como você interage com o modelo: conversar, planejar, executar — e há modos complementares (Debug, Multitask) para casos mais pontuais.

Objetivo: Usar Ask e Agent com confiança; saber quando usar Plan; contextualizar allowlist, escolha de modelos e janela de contexto; conhecer Debug e Multitask em nível introdutório.

Parte expositiva — Ask, Plan, Agent e outros 20 min

Os três modos principais (Ask para perguntas, Plan para planejar antes de executar, Agent para agir) e quando usar cada um. Introdução a Debug e Multitask (usados em casos mais específicos). Discussão sobre allowlist, modelos disponíveis e janela de contexto.

B L O C O 0 4

Recursos dos agentes (Rules, Commands, Skills)

Três alavancas que estendem o comportamento do agente sem repetir contexto em todo prompt.

Objetivo: Saber o que são Rules, Commands e Skills; aplicar duas práticas de workspace mais seguras e conscientes de contexto.

Parte expositiva — Rules, Commands e Skills 15 min

Três recursos que estendem os agentes:

Rules — instruções persistentes (manual de estilo, convenções que o agente sempre segue).
Commands — atalhos que disparam fluxos (/comando).
Skills — pacotes de comportamento e templates instaláveis.

Workspace otimizado e seguro

Duas práticas recomendadas para evitar perda de dados e melhorar performance:

  1. Desabilitar deleção de arquivos nas configurações de segurança do agente.
  2. Manter rules essenciais (como general-guidelines) em always apply — mas cuidado: isso consome janela de contexto em toda interação.
B L O C O 0 5

Cursor no ciclo de produto

Da análise à narrativa e ao planejamento: usar o repositório como "empresa fictícia", gerar entregáveis e preparar o novo fluxo de onboarding para protótipo.

Objetivo: Contexto da Arena Cash, análise de dados, comunicação (slides), workflow PRD do onboarding → épicos/tarefas no Linear. Integrações via MCP (Notion e Linear) são detalhadas no bloco MCPs.

Parte expositiva — Arena Cash e agente dedicado 10 min

Premissa do curso: o repositório oficial está clonado em repos/cursor-para-pms/ (ver Exercício 01). O case Arena Cash fica em repos/cursor-para-pms/case arenacash/ — todos os exercícios deste bloco assumem esses caminhos.

Arena Cash é a empresa fictícia do curso. O repositório traz memo, organograma, design system e demais documentos para você exercitar postura de PM sem depender de dados internos da empresa onde trabalha.

Você vai usar o fluxo nativo do Cursor para criar um agente (menu, Command Palette ou comando com /, conforme a versão instalada — o instrutor mostra ao vivo). O Cursor gera um arquivo Markdown com as instruções permanentes desse agente; esse arquivo é o que você passa a reutilizar nas próximas interações.

Análise de dados e visualização

Como PMs usam análise no dia a dia: partir de arquivos tabulares (CSVs), sintetizar achados e comunicar com um pacote navegável — no mesmo espírito de um projeto com várias páginas HTML de gráficos ou tabelas e um índice que permite alternar entre elas no navegador (sem depender de login ou servidor além de abrir arquivos localmente).

No curso, os dados e o guia visual vêm do case Arena Cash em repos/cursor-para-pms/case arenacash/. Arquivos centrais: dados-quarter-q1.csv, atendimento-q1.csv e design-system-arenacash.md — este último é obrigatório para cores, tipografia e tom da interface do dashboard.

Comunicação: slides, Notion e apresentações

Transformar a análise em narrativa para stakeholders. Em sequência: (1) slides v1 — rápidos, foco no conteúdo; (2) slides v2 — Skill + template HTML Coral; (3) one-page no Notion — mesmo recorte em formato executivo (TLDR, contexto, insights, oportunidades, próximos passos), publicado pelo MCP do Notion, como no roteiro da edição (Notion após slides, antes do PRD).

Ordem sugerida: agente (05) → análise (06) → dashboard (07) → slides (08 e 09) → one-page no Notion via MCP (10) → PRD com /create-prd (11) → protótipo e deploy (12 a 14). Alinha ao roteiro instrutor: narrativa em slides, síntese executiva no Notion (seção 3.5), depois formalização em PRD (seção 3.6).

MCPs

O Model Context Protocol conecta o Cursor a sistemas externos (Notion, Linear, dados, workspace Google, etc.). Este bloco concentra a didática e o setup das integrações usadas no curso.

Objetivo: Entender o que é MCP; conectar Notion e Linear; publicar e gerir tarefas a partir do agente.

Parte expositiva — O que é MCP 10 min

MCP (Model Context Protocol) é um padrão que permite ao Cursor acessar ferramentas externas — banco de dados, APIs, Notion, Linear, Google Drive — sem você precisar copiar/colar manualmente entre plataformas. Para PMs, isso significa gerar PRD, publicar no Notion e criar tarefas no Linear em um fluxo contínuo.

Links úteis e diretórios de MCPs disponíveis estão nas referências complementares.

Configurando Notion e Linear

No curso, você configurará dois MCPs principais via Cursor Marketplace:

Notion MCP

Permite criar, ler e atualizar páginas diretamente do Cursor. Use para publicar análises e documentos em Markdown.

Setup: Settings → Cmd + Shift + J (Mac) ou Ctrl + Shift + J (Windows) → @cursor/marketplace → buscar Notion → Enable/Install → conectar conta.

Linear MCP

Permite criar épicos, issues e sincronizar status. Use para quebrar a PRD em tarefas acionáveis.

Setup: Settings → Cmd + Shift + J (Mac) ou Ctrl + Shift + J (Windows) → @cursor/marketplace → buscar Linear → Enable/Install → conectar conta.
